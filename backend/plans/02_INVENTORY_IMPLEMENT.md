
## Step 1: Entity — `InventoryItem.java`

**File:** `entity/InventoryItem.java`

Create a class with these annotations and fields:

```
@Entity + @Table(name = "inventory_items")

Fields:
  id             → Long, @Id + @GeneratedValue(strategy = GenerationType.IDENTITY)
  user           → User, @ManyToOne(fetch = FetchType.LAZY) + @JoinColumn(name = "user_id", nullable = false)
  name           → String, @Column(nullable = false)
  category       → String, @Column(nullable = false)
  productionCost → BigDecimal, @Column(nullable = false)
  sellingPrice   → BigDecimal, @Column(nullable = false)
  stock          → Integer, @Column(nullable = false)
  createdAt      → LocalDateTime
  updatedAt      → LocalDateTime
```

### What to learn here

- **`@Entity` + `@Table`** — marks this class as a database table. Without `@Table`, JPA uses the class name as the table name.
- **`@Id` + `@GeneratedValue(IDENTITY)`** — primary key, auto-generated by Postgres (BIGSERIAL).
- **`@ManyToOne(fetch = LAZY)`** — foreign key relationship. Many items belong to one user. `LAZY` = don't load the User object until you actually call `item.getUser()`. This is a performance optimization.
- **`@JoinColumn(name = "user_id")`** — tells Hibernate which DB column stores the FK value.
- **`BigDecimal` for money** — never use `double` or `float` for prices. They have floating-point rounding errors (e.g. `0.1 + 0.2 = 0.30000000000000004`). `BigDecimal` is exact.
- **`@Column(nullable = false)`** — maps to `NOT NULL` in the DB. If you try to save a null, Hibernate throws an exception before it even hits the DB.

### Timestamps

You have two options for auto-setting `createdAt` and `updatedAt`:

**Option A — JPA lifecycle callbacks (recommended):**
```java
@PrePersist
protected void onCreate() {
    createdAt = LocalDateTime.now();
    updatedAt = LocalDateTime.now();
}

@PreUpdate
protected void onUpdate() {
    updatedAt = LocalDateTime.now();
}
```
`@PrePersist` runs before the first INSERT. `@PreUpdate` runs before every UPDATE.

**Option B — Set manually in the service layer.** Works fine but you have to remember to do it every time.

### Column naming

JPA auto-converts camelCase to snake_case: `productionCost` becomes `production_cost` in the DB. You don't need `@Column(name = "production_cost")` unless your naming strategy is configured differently.

### Don't forget

- Generate getters and setters (or use Lombok `@Getter @Setter` if you want, but the existing code doesn't use Lombok)
- Add a no-args constructor (JPA requires it)
- Look at `User.java` for reference on how the existing entity is structured

## Step 2: DTO — `InventoryItemRequest.java`

**File:** `dto/InventoryItemRequest.java`

This defines what the client is allowed to send. No `id`, no `user`, no timestamps — just the data fields.

```
Fields:
  name           → @NotBlank String
  category       → @NotBlank String
  productionCost → @NotNull BigDecimal
  sellingPrice   → @NotNull BigDecimal
  stock          → @NotNull @Min(0) Integer
```

### What to learn here

- **Why a DTO instead of reusing the entity?** Separation of concerns. The entity is your DB model. The DTO is your API contract. You don't want the client sending `id` or `user` — those are set server-side.
- **Validation annotations** come from `jakarta.validation.constraints`:
  - `@NotBlank` — not null AND not empty AND not just whitespace (strings only)
  - `@NotNull` — not null (works on any type)
  - `@Min(0)` — value must be >= 0
  - These validations run automatically when you use `@Valid` in the controller (Step 5)
- **Java records** — try using `public record InventoryItemRequest(...)` instead of a class. Records auto-generate the constructor, getters, `equals()`, `hashCode()`, and `toString()`. Perfect for DTOs since they're just data carriers.

### Reference

Look at `LoginRequest.java` and `SignupRequest.java` for how existing DTOs are structured.

## Step 3: Repository — `InventoryItemRepository.java`

**File:** `repository/InventoryItemRepository.java`

```java
public interface InventoryItemRepository extends JpaRepository<InventoryItem, Long> {
    List<InventoryItem> findByUserIdOrderByCreatedAtDesc(Long userId);
    Optional<InventoryItem> findByIdAndUserId(Long id, Long userId);
}
```

### What to learn here

- **You write zero SQL.** Spring Data JPA reads the method name and generates the query:
  - `findByUserId` → `WHERE user_id = ?`
  - `OrderByCreatedAtDesc` → `ORDER BY created_at DESC`
  - `findByIdAndUserId` → `WHERE id = ? AND user_id = ?`
- **`JpaRepository<InventoryItem, Long>`** — the first type is the entity, the second is the primary key type. This gives you `save()`, `findById()`, `findAll()`, `deleteById()`, etc. for free.
- **`Optional<InventoryItem>`** — for queries that might return nothing. Forces you to handle the "not found" case explicitly instead of getting a null pointer.
- **`findByIdAndUserId` is a security method** — it ensures user A can't access user B's items just by guessing the ID. Always scope queries by userId.

### Reference

Look at `UserRepository.java` — same pattern but with different query methods.

## Step 4: Service — `InventoryService.java`

**File:** `service/InventoryService.java`

Annotate with `@Service`. Inject both `InventoryItemRepository` and `UserRepository` via constructor.

### Methods to implement

**`List<InventoryItem> getAll(Long userId)`**
- One line — call `repository.findByUserIdOrderByCreatedAtDesc(userId)` and return

**`InventoryItem create(Long userId, InventoryItemRequest req)`**
1. Fetch the User: `userRepository.findById(userId).orElseThrow()`
2. Create a new `InventoryItem` object
3. Set all fields from `req` (name, category, productionCost, sellingPrice, stock)
4. Set the `user` field to the fetched User
5. Set `createdAt` and `updatedAt` to `LocalDateTime.now()` (skip if you used `@PrePersist`)
6. `return repository.save(item)`

**`InventoryItem update(Long userId, Long itemId, InventoryItemRequest req)`**
1. Fetch existing item: `repository.findByIdAndUserId(itemId, userId)`
2. `.orElseThrow(() -> new ResponseStatusException(HttpStatus.NOT_FOUND, "Item not found"))`
3. Update fields from `req` on the fetched item
4. Update `updatedAt` (skip if you used `@PreUpdate`)
5. `return repository.save(item)`

### What to learn here

- **`@Service`** — a Spring stereotype annotation. It tells Spring "this is a bean, manage its lifecycle." Spring creates one instance and injects it wherever needed (singleton by default).
- **Constructor injection** — `public InventoryService(InventoryItemRepository repo, UserRepository userRepo)`. Spring auto-detects the constructor and injects the dependencies. This is preferred over `@Autowired` on fields because:
  - Dependencies are explicit and visible
  - The object is always fully initialized
  - Easier to test (just pass mocks in the constructor)
- **`repository.save()`** — works for both INSERT and UPDATE. If the entity has no `id` (null), it inserts. If it has an `id`, it updates.
- **`ResponseStatusException`** — a convenient way to return HTTP errors from the service layer. `new ResponseStatusException(HttpStatus.NOT_FOUND)` sends a 404 response. Import from `org.springframework.web.server`.
- **`.orElseThrow()`** — unwraps an `Optional`. If the Optional is empty, it throws the exception you provide.

### Reference

Look at `AuthService.java` for the injection pattern and how it uses repositories.

## Step 5: Controller — `InventoryController.java`

**File:** `controller/InventoryController.java`

```
@RestController
@RequestMapping("/api/v1/inventory")
```

Inject `InventoryService` via constructor. Three endpoints:

### GET `/` — List all items
```
@GetMapping
public List<InventoryItem> getAll(@AuthenticationPrincipal User user) {
    return service.getAll(user.getId());
}
```

### POST `/` — Create item
```
@PostMapping
@ResponseStatus(HttpStatus.CREATED)
public InventoryItem create(
    @AuthenticationPrincipal User user,
    @Valid @RequestBody InventoryItemRequest req
) {
    return service.create(user.getId(), req);
}
```

### PUT `/{id}` — Update item
```
@PutMapping("/{id}")
public InventoryItem update(
    @AuthenticationPrincipal User user,
    @PathVariable Long id,
    @Valid @RequestBody InventoryItemRequest req
) {
    return service.update(user.getId(), id, req);
}
```

### What to learn here

- **`@RestController`** = `@Controller` + `@ResponseBody`. Every method return value is automatically serialized to JSON.
- **`@RequestMapping("/api/v1/inventory")`** — base path for all endpoints in this controller.
- **`@AuthenticationPrincipal User user`** — Spring Security injects the currently authenticated user. This works because your `JwtAuthFilter` already puts the User object into the SecurityContext. You get the user for free — no manual token parsing needed.
- **`@Valid`** — triggers the validation annotations on the DTO (`@NotBlank`, `@Min`, etc.). Without `@Valid`, those annotations are ignored. If validation fails, Spring auto-returns a 400 with error details.
- **`@RequestBody`** — tells Spring to parse the incoming JSON into the DTO object.
- **`@PathVariable`** — extracts `{id}` from the URL path.
- **`@ResponseStatus(HttpStatus.CREATED)`** — changes the default response code from 200 to 201 for the POST endpoint. REST convention: 201 = "resource created."

### Security — already handled

Your `SecurityConfig.java` already requires JWT for everything except `/api/v1/auth/**`. So `/api/v1/inventory/**` is automatically protected. You don't need to add anything.

### Watch out for circular JSON

When Spring serializes `InventoryItem` to JSON, it will try to include the `user` field, which includes the user's items, which includes the user... infinite loop. Fix with one of:
- `@JsonIgnore` on the `user` field in the entity
- `@JsonIgnoreProperties("password")` if you want some user fields but not all
- A response DTO (cleanest, but more code — fine to skip for now)

### Reference

Look at `AuthController.java` for the basic structure.

## Step 6: Verify

Start the server and test with curl:

```bash
# 1. Login to get a token
TOKEN=$(curl -s -X POST http://localhost:8080/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"you@test.com","password":"yourpass"}' | jq -r '.token')

# 2. Create an item
curl -X POST http://localhost:8080/api/v1/inventory \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"Gojo Print A4","category":"Prints","productionCost":2.50,"sellingPrice":15.00,"stock":45}'

# 3. List items
curl http://localhost:8080/api/v1/inventory \
  -H "Authorization: Bearer $TOKEN"

# 4. Update item (use the id from step 2)
curl -X PUT http://localhost:8080/api/v1/inventory/1 \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"Gojo Print A4 (Updated)","category":"Prints","productionCost":3.00,"sellingPrice":18.00,"stock":40}'
```

### Common errors and fixes

| Error | Likely cause |
|-------|-------------|
| 403 Forbidden | Token expired or missing `Bearer ` prefix |
| 500 on create | Missing `@JoinColumn` or null user reference |
| Infinite JSON loop | Missing `@JsonIgnore` on the `user` field |
| Validation not working | Missing `@Valid` before `@RequestBody` in controller |
| Column not found | Hibernate naming mismatch — check `application.properties` naming strategy |
